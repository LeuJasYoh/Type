# 代码注释的写法与归置

本文件是"代码注释"这件事的单一权威：什么必须留在代码里、什么必须上移 docs、
什么该变成测试。规范改了改这里，并同步 AGENTS.md 的「文档地图」。

改注释不动行为：tools/equivcheck 只比函数体（go/parser 丢弃注释），所以注释重写
拿不到任何自动等价证明，它丢的是信息而不是行为。护栏只有一条：本文件 + 人工复核。

## 判据只有一条：这条信息能不能从代码推出

判据是"只读代码、跑一遍测试，能不能重新得到这个结论"，不是"读起来顺不顺"。
能推出的一律不写。推不出的那三类才是注释的价值所在：

1. **实测结论**（"125% 下 1024 → 1023"、"300 轮里 246 轮注入两遍"）；
2. **被否决方案及理由**（"别改用取消计数器 + 基线那套"）；
3. **跨文件的时序与并发约定**（复检必须紧贴 SendPaste、取消标志在哪一步清）。

## 三种形态

### 形态 1：局部-为什么（留在代码里，≤5 行）

紧贴 1–3 行代码、离开这段就看不懂的信息。例：某个 Win32 常量为何用 ^uintptr(n)
表达、某个 sleep 为何必须在这个位置。这是唯一必须留在代码里的形态。

### 形态 2：跨文件指针（格式冻结）

    见 docs/invariants.md「任务槽与并发启动」

- 必须形如 见 docs/<文件名>.md「<小节标题>」——见 后一个空格、标题用「」。
- 指针是"权威在那边"的意思：写了指针就**不再复述**内容。同一事实有两份散文，
  改一处漏一处，比没有注释更坏。
- 闸门 TestDocSectionReferencesResolve 校验三件事：目标文件存在、小节名是文档里的
  真实标题、不允许裸引用（没有「」的写法）。

### 形态 3：文件头（≤5 行）

包/文件职责 + 不变量索引。历史叙事不进文件头（版本演进、拆分前的行数这类内容
属于 docs 或 git 历史，不属于文件头）。

## 归置判据：一条信息只放一处

| 信息 | 去处 |
|---|---|
| 与紧邻代码强绑定的"为什么必须这样" | 形态 1，留原地 |
| 跨函数/跨文件的时序与并发约定 | docs/invariants.md，代码留形态 2 指针 |
| 版本演进、实测数据与样本量、被否决的方案及理由 | docs/invariants.md；只与某次发布绑定的进 release-notes/ |
| 能用断言表达的约束 | 写成用例（用例名带 ① ② 编号），注释里最多留一行指针 |
| 签名/字段/流程的复述 | 删 |
| // ─── 小节 ─── 导航线 | 留（承担文件内导航，删了反而难读） |

**已有决定，动它要先改文档**：docs/invariants.md「其它不变量」写明"Win32 怪癖的
注释保留在 internal/win32 的实现内……重构时勿删"。形态 1 优先留在原地这条，对平台层
尤其成立；要上移先改那份文档，并同步本文。

## 长度预算

- 单块连续 // **≤ 10 行**，超过就必须上移或拆成多块。
- **Go 源码不许用块注释**：源码解析类闸门只剥整行 //，块注释会被当成代码参与断言；
  判定走 go/parser，别用字符串找斜杠星号（会命中字符串字面量里的同一组合）。
- 前端 .ts / .vue 允许 /** */（TS 的生态惯例），但同样 ≤ 10 行。
- 文件头 ≤ 5 行。

## 闸门

闸门只有一处：**tools/repo-check**（go test ./... 会一并跑到；它与产品行为无关，
所以不放在 cmd/type 的测试里）。

| 检查 | 判据 |
|---|---|
| Go 源码零块注释 | go/parser 判定（TestNoBlockCommentsInGo） |
| 单块 ≤ 10 行 | 扫描 cmd/internal/tools/frontend 下全部源码（TestCommentBlockBudget） |
| 指针冻结且可解析 | 文件存在 + 小节标题存在 + 零裸引用（TestDocSectionReferencesResolve） |
| 规范登记进 AGENTS.md | 文档地图里有链接（TestCommentStyleSpecRegistered） |
| 仓库内 md 本地链接存在 | TestMarkdownLinksResolve（放在同一包，属于文档卫生） |

**闸门守"形态与可解析性"，不守"内容正确"**：内容正确性靠提交前人工核对，别把
全绿当成"注释写得对"。闸门的基线数字一律写在测试里，文档不重复记录（写过就会漂）。

## 红线

- 冻结文案一个字不改（清单见 docs/behavior-contract.md）；重写注释不是改文案的窗口。
- 不引入 Go 块注释；不把指针改写成 docs/x.md#节 这类新格式（要换格式就先换闸门）。
- 注释重写不行为。真要做也必须一个文件一次提交、先跑 tools/equivcheck，
  并逐个核对"上移 docs"是否真的落进了目标文档。
