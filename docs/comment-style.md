# 代码注释的写法与归置（含重写台账）

本文件是"代码注释"这件事的单一权威：什么必须留在代码里、什么必须上移 docs、什么该变成
测试，以及守护它们的闸门。规范改了改这里，并同步 AGENTS.md 的「文档地图」。

改注释不动行为 —— `tools/equivcheck` 只比函数体（go/parser 丢弃注释），所以注释重写
**拿不到任何自动等价证明**，它丢的是信息而不是行为。唯一的护栏是
`docs/comment-ledger/` 台账逐条销账，别指望测试能拦住"少写了一句为什么"。

## 判据只有一条：这条信息能不能从代码推出

判据是"只读代码、跑一遍测试，能不能重新得到这个结论"，不是"读起来顺不顺"。
能推出的一律不写。推不出的那三类才是注释的价值所在：

1. **实测结论**（"125% 下 1024 → 1023"、"300 轮里 246 轮注入两遍"）；
2. **被否决方案及理由**（"别改用取消计数器 + 基线那套"）；
3. **跨文件的时序与并发约定**（复检必须紧贴 SendPaste、取消标志在哪一步清）。

## 三种形态

### 形态 1：局部-为什么（留在代码里，≤5 行）

紧贴 1–3 行代码、离开这段就看不懂的信息。例：某个 Win32 常量为何用 `^uintptr(n)`
表达、某个 `sleep` 为何必须在这个位置。这是唯一必须留在代码里的形态。

### 形态 2：跨文件指针（格式冻结）

```
见 docs/invariants.md「任务槽与并发启动」
```

- 必须形如 `见 docs/<文件名>.md「<小节标题>」` —— `见` 后一个空格、标题用「」。
- 指针是"权威在那边"的意思：写了指针就**不再复述**内容。同一事实有两份散文，
  改一处漏一处，比没有注释更坏。
- 闸门 `TestDocRefFormatFrozen` 只允许基线内的裸引用，基线只减不增。

### 形态 3：文件头（≤5 行）

包/文件职责 + 不变量索引。历史叙事不进文件头（`taskrun.go` 顶上那段"拆分前是 256 行/
9 个参数"属于形态 2 的候选）。

## 归置判据：一条信息只放一处

| 信息 | 去处 |
|---|---|
| 与紧邻代码强绑定的"为什么必须这样" | 形态 1，留原地 |
| 跨函数/跨文件的时序与并发约定 | `docs/invariants.md`，代码留形态 2 指针 |
| 版本演进、实测数据与样本量、被否决的方案及理由 | `docs/invariants.md`；只与某次发布绑定的进 `release-notes/` |
| 能用断言表达的约束 | 写成用例（用例名带 ① ② 编号），注释里最多留一行指针 |
| 签名/字段/流程的复述 | 删 |
| `// ─── 小节 ───` 导航线 | 留（承担文件内导航，删了反而难读） |

**已有决定，动它要先改文档**：`docs/invariants.md`「其它不变量」写明"Win32 怪癖的注释
保留在 internal/win32 的实现内……重构时勿删"。形态 1 优先留在原地这条，对平台层尤其
成立；要上移先改那份文档，并同步本文。

## 长度预算

- 单块连续 `//` **≤ 10 行**，超过就必须上移或拆成多块。
- **Go 源码不许用 `/* */` 块注释**：`cmd/type/build_contract_test.go` 的 `codeLines` 只剥
  整行 `//`，块注释会被当成代码参与 `Contains` 断言（正是那份文件自己注释里防的
  "假报警器"）。闸门用 `go/parser` 判定 —— 别用字符串找 `/*`，那会连**字符串字面量
  里的**斜杠星号一起命中（本闸门第一版就自己命中了自己）。
- 前端 `.ts` / `.vue` 允许 `/** */`（TS 的生态惯例，现状 4 处、最长 5 行），但同样 ≤ 10 行。
- 文件头 ≤ 5 行。

## 台账：重写期间的防丢机制

`docs/comment-ledger/<area>.md`，每个区域一份（`typing` / `win32` / `app`），
逐条登记"不可从代码推出"的事实：

```
| ID | 事实 | 来源 | 类别 | 去向 |
| T-001 | 取消标志只能在 beginRun 清，不能在 Start 清 | internal/typing/typing.go:316-318 | B | 上移 docs/invariants.md「任务槽与并发启动」，代码留一行指针 |
```

- ID 前缀按区域：`T-`（internal/typing）、`W-`（internal/win32）、`A-`（cmd/type、frontend、tools）。
- 类别：`A` 局部-为什么 / `B` 跨文件设计与历史 / `C` 已在 docs 或契约里重复 / `D` 复述代码。
- 去向必须以下列之一**开头**：`留原地` / `上移` / `转测试` / `删`。
- 来源列的写法（闸门会解析）：`路径:行号` 或 `路径:起始-结束`，同一路径下多个行段用逗号
  连接（`cmd/type/main.go:21-24,136-144`），多个来源之间用分号分隔（`…; docs/invariants.md:295-297`）。
  闸门校验路径真实存在、且落在本区域的目录范围内；**行号内容不做比对**（重写期必然漂移）。
- 同一事实在多处出现时合并成一条，把全部来源行号列出来（那正是去重的输入）。
- **重写一个文件前**先把它名下的条目列全，**重写之后**逐条确认去向已落地，一条不落才提交。
- 台账用完不必删，留着备查即可；条数即存档下限，由闸门守着。仍有效的长期内容沉进 `docs/invariants.md`。

## 闸门与基线

闸门在 `cmd/type/comment_contract_test.go`，扫描范围覆盖重写顺序里的全部区域
（`cmd`、`internal`、`tools`、`frontend/src`、`frontend/test`、`frontend/tools`）：

| 检查 | 现状基线（只减不增） |
|---|---|
| Go 源码零块注释（`go/parser` 判定；前端 `/** */` 是生态惯例，不计） | 0 处 |
| 单块 ≤ 10 行（Go 数连续 `//`；前端与 `.mjs` 数 `//` 与 `/* */` 之和） | **0 块**（重写前是 15 个文件共 20 块，四批完成后基线已全部下调到 0） |
| 指针格式冻结，且**指向的文档必须存在** | **0 条裸引用**（三条改成了冻结格式，一条随重写消失） |
| 台账：ID 形状/前缀/唯一性 + 类别 + 去向 + 来源文件存在且属本区域 + 条数下限 | typing 43 / win32 43 / app 42（数字写在闸门里；减少必须同步改常量，那会出现在 diff 里） |
| 规范以链接形式登记进 AGENTS.md 的文档地图 | 已登记 |

实际数超过基线即红；某个文件的实际数降到基线以下时，**顺手把基线调下来**（测试会
`t.Logf` 出来），基线不降就等于闸门在放水。

**已知不设闸门的几件事**（靠人销账，别误以为它们被自动守着）：注释总量没有上限
（只管单块长度）；行中起头的 `/* */` 块（`code; /* …`）不计入预算；台账"来源"的行号
内容不做比对（越界行号、张冠李戴都查不出，只查文件存在与区域前缀）；"上移 docs"是否真的
落进了目标文档，没有任何环节验证；AGENTS.md 的登记只认"链接出现在文件任意位置"，不要求
它落在文档地图表内。

## 重写顺序（风险从低到高，一个文件一次提交）

1. `tools/`：不进产品链路，最安全。**已完成**（4 个文件，长块 4 → 0；代码逐 token 零改动）；
2. `frontend/src/` + `frontend/test` + `frontend/tools`：**已完成**（12 个文件，长块 3 → 0）；
   按铁律 2 跑了一次 `scripts/build.ps1` 核对产物是否漂移；
3. `internal/win32/`：**已完成**（8 个文件，长块 8 → 0）。"注释留在实现内"那条既有决定全程遵守，
   A 类 28 条一条没搬走；
4. `internal/typing/` 与 `cmd/type/`：**已完成**（7 个文件，长块 5 → 0）。冻结文案、phase 常量名、
   `msgCountdownFormat` 的位置与两个契约测试的字面量断言全部逐字未动（核验用 token 流证明）。

四批的逐文件数字、销账与**已知偏离**都在 `docs/comment-ledger/progress.md`；每批各有一份独立核验
报告（`batch1..4-verification.md`）。**重写期间发生的偏差只有一类**：台账写"上移 docs"但那份文档
没有等价段落的条目，按"不凭空上移"留在代码里压缩保留（信息未丢，详见 progress.md）。

**不要一次全仓重写**：diff 无法审查，且上面那类正则断言读的是源码字面形态。

## 红线

- 冻结文案一个字不改（清单见 `docs/behavior-contract.md`）——重写注释不是改文案的窗口；
  三条漂移中止文案不许合并。
- 下列三条注释删了必然回归，重写后信息密度不得低于原来：
  `cmd/type/main.go` 的窗口尺寸与样式段（WM_DPICHANGED / `HintFixed` / `SetSize` 与
  `SetWindowClientRect` 的先后）、`internal/typing/typing.go` 的"`SendPaste` 返回后立刻
  复检"段、`internal/win32/win32_instance.go` 的"事后 `GetLastError` 已被运行时清零"段。
- 指针层全程非空：`TestDocSectionReferencesResolve` 在 `checked == 0` 时直接报错。
- 不引入块注释；不把指针改写成 `docs/x.md#节` 这类新格式（要换格式就先换闸门）。
